# SharpCode

A small LeetCode-style app for C#: add problems with test cases, pick one, write a
solution in the browser, and have it compiled and judged against the test cases.
The UI is available in English (default) and Spanish, problems are grouped into
**School** (classroom exercises) and **Gym** (classic algorithm problems), and a
**Sandbox** page runs free-form console programs with user-provided stdin. Users sign in
with Google; submissions, per-problem drafts and sandbox scripts are stored per user.

```
client/   Vite + Vue 3 + TypeScript front end (CodeMirror editor, Markdown statements)
server/
  SharpCode.Api/     ASP.NET Core minimal API, EF Core + SQLite, Roslyn compiler
  SharpCode.Runner/  Disposable console process that executes a compiled solution
```

## How judging works

1. The API compiles the submitted source with Roslyn into an in-memory assembly
   (`System`, `System.Collections.Generic`, `System.Linq`, `System.Text` are imported
   implicitly). Compile errors are returned with line/column.
2. The assembly plus the test cases are handed to `SharpCode.Runner`, a separate
   process. It instantiates the problem's class (default `Solution`), calls the
   configured method with the arguments from each test case, and prints one JSON
   result per test.
3. Arguments and expected outputs are JSON. Input is a JSON array of arguments
   (`[[2,7,11,15], 9]`), the expected value is the JSON-serialized return value
   (`[0,1]`). Comparison is structural JSON equality with a small tolerance for numbers.
4. Each test runs on its own thread with the problem's time limit. On a timeout the
   runner reports it and exits; on a crash (stack overflow, `Environment.Exit`) the
   API detects the missing results and reports a runtime error. Either way the API
   process is never affected.
5. **Run** executes only the visible sample cases and stores nothing. **Submit**
   executes every case, hidden ones included, and records the submission.
6. Every problem has exactly **5 visible + 20 hidden** test cases; the API rejects
   anything else.

## Built-in problems

`server/SharpCode.Api/Data/seed.json` holds the 14 built-in problems (10 School, 4 Gym)
with English and Spanish texts. It is generated by `tools/generate_seed.py`, which
computes every expected output from a reference implementation, so edit the script and
rerun it instead of editing the JSON. On startup the API inserts any seeded problem whose
slug is missing from the database; existing problems are never overwritten.

## Documentation

`client/src/docs/topics.ts` holds the C# basics (14 topics, English and Spanish) with runnable
examples; every example is a complete console program that the **Open in sandbox** button loads
into the Sandbox. Problems point to topics through `docLinks` (set in `tools/generate_seed.py`),
shown as "Useful documentation" on the problem page. Seeded problems are re-synced from
`seed.json` on every start, so the seed file is the source of truth for them.

## Accounts

Sign-in uses Google Identity Services on the client and the Google ID token is verified on
the server (`Google.Apis.Auth`), which then issues its own bearer token (HS256 JWT, 30 days,
refreshed on use). Anonymous visitors can read problems and docs; running, submitting, the
sandbox, drafts and scripts require an account. Anyone with a Google account can sign in.

Configuration:

- `Google:ClientId` (`Google__ClientId`): the OAuth client id. Public, so it lives in
  `fly.toml` and `appsettings.Development.json`. The Google Cloud OAuth client must list the
  app origins (`http://localhost:5173`, `https://sharpcode-csharp.netlify.app`) under
  *Authorized JavaScript origins*.
- `Auth:Secret` (`Auth__Secret`): the JWT signing key, at least 32 characters. Required outside
  Development (`fly secrets set Auth__Secret=…`); development falls back to a fixed value.

Per user the database keeps `Submissions`, `ProblemDrafts` (autosaved editor contents, one
per problem), `SandboxDrafts` (current sandbox program) and `SandboxScripts` (named
programs). The `AddUsers` migration deleted the submissions that existed before accounts.

## Admin

Creating, editing and deleting problems requires a shared secret. Set it as
`Admin:Token` (`Admin__Token` as an environment variable, `fly secrets set Admin__Token=…`
on Fly). The client's **Admin** page stores the token in the browser and sends it as the
`X-Admin-Token` header. In development `appsettings.Development.json` sets it to
`dev-admin-token`. The admin page and the problem editor are only compiled into development
builds; production has no way to add problems.

## Sandbox

`POST /api/sandbox/run` compiles the code as a console application and runs it in its own
process with the provided stdin (5 s limit, 64 KB of output). `Console.ReadLine()` returns
`null` once the input is exhausted.

The runner is a plain child process, not a sandbox: user code has the same OS
permissions as the API. That is fine for a personal, local tool. Do not expose it to
untrusted users without adding real isolation (container, seccomp, etc.).

## Prerequisites

- .NET SDK 10 (`dotnet --version`)
- Node.js 22+

## Run it

Terminal 1, API on http://localhost:5055:

```bash
cd server/SharpCode.Api
dotnet run
```

Terminal 2, client on http://localhost:5173 (proxies `/api` to the API):

```bash
cd client
npm install
npm run dev
```

The SQLite database (`server/SharpCode.Api/sharpcode.db`) is created and migrated on
first start (EF Core migrations in `server/SharpCode.Api/Migrations`) and seeded with the
built-in problems. Delete the file to reset. After changing the model, add a migration:

```bash
cd server/SharpCode.Api
dotnet ef migrations add <Name>
```

## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/problems?lang=en\|es` | List problems (category, solved flag), localized titles |
| GET | `/api/problems/{id-or-slug}?lang=` | Problem with its visible test cases, localized |
| GET | `/api/problems/{id-or-slug}/full` | Admin: hidden test case details and translations |
| POST | `/api/problems` | Admin: create a problem (5 visible + 20 hidden cases) |
| PUT | `/api/problems/{id}` | Admin: update; `testCases` replaces the whole set |
| DELETE | `/api/problems/{id}` | Admin: delete a problem, its cases and submissions |
| GET | `/api/admin/check` | 200 when the `X-Admin-Token` header is valid |
| GET | `/api/config` | Public configuration (`googleClientId`) |
| POST | `/api/auth/google` | Exchange a Google ID token for a session (`token`, `user`) |
| GET | `/api/auth/me` 🔒 | Current user; includes a fresh `token` when the old one is ageing |
| POST | `/api/complete` 🔒 | Roslyn completions for the editor (`code`, `position`) |
| POST | `/api/sandbox/run` 🔒 | Compile and run a console program (`code`, `stdin`) |
| GET/PUT | `/api/sandbox/draft` 🔒 | The user's current sandbox program (`code`, `stdin`) |
| GET/POST | `/api/sandbox/scripts` 🔒 | The user's named scripts (`name`, `code`, `stdin`) |
| PUT/DELETE | `/api/sandbox/scripts/{id}` 🔒 | Update or delete a named script |
| POST | `/api/problems/{id}/run` 🔒 | Compile and run the sample cases |
| POST | `/api/problems/{id}/submit` 🔒 | Compile, run all cases, record a submission |
| GET | `/api/problems/{id}/submissions` 🔒 | The user's submission history for a problem |
| GET | `/api/submissions/{id}` 🔒 | One of the user's submissions with its full judge result |
| GET/PUT/DELETE | `/api/problems/{id}/draft` 🔒 | The user's autosaved editor contents for a problem |

🔒 requires `Authorization: Bearer <token>`.

Problem payload:

```json
{
  "title": "Two Sum",
  "slug": "two-sum",
  "description": "Markdown…",
  "difficulty": "Easy",
  "category": "Gym",
  "translations": { "es": { "title": "Suma de dos", "description": "Markdown…" } },
  "starterCode": "public class Solution { public int[] TwoSum(int[] nums, int target) { … } }",
  "className": "Solution",
  "methodName": "TwoSum",
  "timeLimitMs": 2000,
  "testCases": [
    { "input": "[[2,7,11,15], 9]", "expected": "[0,1]", "isHidden": false }
  ]
}
```
